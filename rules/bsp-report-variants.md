# Варианты отчётов БСП: почему их не видно

Правило о том, как заставить БСП показать варианты отчёта своих блоков (`Преф_`).
Выстрадано 2026-09-06: на поиск причины ушло около восьми итераций, хотя решение оказалось в четырёх строчках регистрации.

Применяется: при добавлении отчёта или нового варианта в схему компоновки; при жалобе «вариантов нет» или «варианты называются одинаково».

Родственное правило — `bsp-print-document.md`: там та же природа («объект корректен, но БСП его не опрашивает»).

---

## Главное: нужны ЧЕТЫРЕ вещи, и не хватает обычно всех сразу

Вариант в схеме компоновки — необходимое, но далеко не достаточное условие.

| # | Что | Где | Симптом при отсутствии |
|---|---|---|---|
| 1 | Модуль менеджера отчёта: `ПриОпределенииНастроек` + `НастроитьВариантыОтчета` | `Report.<Имя>.ManagerModule` | описаний и имён вариантов нет |
| 2 | Регистрация **отчёта** | `Преф_ОбщегоНазначения.НастроитьВариантыОтчетов` | БСП не опрашивает модуль менеджера |
| 3 | Регистрация **раздела** | расширение `Преф_ДоработкиТиповогоФункционала`, перехват `ОпределитьРазделыСВариантамиОтчетов` | панели отчётов у раздела нет вовсе |
| 4 | Перестроение кэша БСП | запуск клиента с `/CЗапуститьОбновлениеИнформационнойБазы` | список вариантов остаётся прежним |

### Про п. 3 — где именно править

Типовой `ВариантыОтчетовПереопределяемый` **вне git** (`.gitignore` на весь `src/**`), правка там потеряется при обновлении БП. В проекте уже есть перехват в расширении, рядом с `Преф_НастроитьВариантыОтчетов` — добавлять туда же.

### Про п. 4 — почему обновление БД не помогает

БСП хранит варианты в справочнике `ВариантыОтчетов` и перезаполняет его **только при обновлении информационной базы**, а оно запускается по смене версии конфигурации, а не по «Обновить конфигурацию БД». Обработчики с `Версия = "*"` есть в `Преф_ОбновлениеИнформационнойБазы` (зарегистрирован в `ОбновлениеИнформационнойБазыБП`), но без запуска обновления ИБ они не выполняются.

Панель отчётов раздела — это **не** список объектов в навигации раздела: там отчёт всегда одной строкой, вариантов в ней не бывает. Искать надо команду «Отчёты».

---

## Имена вариантов: одинаковые названия в списке

Без явного `НастройкиВарианта.Наименование` БСП подставляет каждому варианту **синоним отчёта** — в списке они выглядят одинаково и различить их нельзя.

```bsl
НастройкиВарианта = ВариантыОтчетов.ОписаниеВарианта(Настройки, НастройкиОтчета, "КлючВарианта");
НастройкиВарианта.Наименование = НСтр("ru = 'Короткое понятное имя'");
НастройкиВарианта.Описание     = НСтр("ru = 'Что показывает и в каких единицах.'");
```

`<dcsset:presentation>` в самой схеме задавать бесполезно: во всей конфигурации, включая типовые отчёты БП, он пустой.

Наименование тоже живёт в справочнике `ВариантыОтчетов` — после правки нужен п. 4.

## ★ Грабля: один отчёт без модуля менеджера ломает весь список

`ВариантыОтчетов.НастроитьОтчетВМодулеМенеджера` обращается к модулю менеджера отчёта. Если отчёта в списке нет модуля, вызов **обрывает настройку всех остальных** отчётов процедуры — молча, без ошибки в EDT.

Проверка перед правкой списка:

```bash
cd <проект>/src/Reports
for r in Преф_*; do
  [ -f "$r/ManagerModule.bsl" ] || { echo "НЕТ МОДУЛЯ: $r"; continue; }
  grep -q "Процедура ПриОпределенииНастроек" "$r/ManagerModule.bsl" || echo "БЕЗ ПриОпределенииНастроек: $r"
done
```

В список включать только отчёты, прошедшие проверку.

## Смежное: порядок разделов и иконки

**Порядок разделов в панели** задаётся только в `Configuration/CommandInterface.cmi`, блок `<subsystemsOrder>`. Подсистемы, которой там нет, платформа ставит произвольно. Файл типовой, но взят под версионирование исключением в `.gitignore` — иначе правка теряется при обновлении БП.

**Иконка подсистемы** — тег `picture` в `.mdo` подсистемы:

```xml
<picture xsi:type="core:PictureRef">
  <picture>CommonPicture.Имя</picture>
</picture>
```

Требует объявлений `xmlns:xsi` и `xmlns:core` в корневом теге — у свежесозданных подсистем их нет.

**`modify_metadata` не адресует вложенные подсистемы:** на корректный FQN вида `Subsystem.Родитель.Subsystem.Имя` отвечает «Node not found», хотя `list_subsystems` этот же FQN и выдаёт. Свойство приходится дописывать в `.mdo` — это добавление свойства существующему объекту, состав конфигурации не затрагивается.

**Размер картинки:** типовые иконки разделов БП — набор масштабов в `Picture.zip` (база `100.png` = 32×32 при глифе 16pt, плюс 85/125/150/175/200/300/400 %). Одиночный PNG 16×16 тоже работает — так сделаны картинки нашего блока. Детальный рисунок на 16 пикселях превращается в пятно: не больше двух-трёх фигур, рисовать в 8-кратном размере и уменьшать с LANCZOS.

## ★ Отчёт без регистрации может не открываться вовсе

Проверено 2026-09-13 на `одном из отчётов блока`: форма отчёта зависала при открытии — не при формировании,
а ещё до нажатия «Сформировать». Схема и запрос были чистые (`validate_query` без замечаний), в коде
причины не нашлось. Отличие от всех работающих отчётов проекта — ровно три вещи из таблицы выше:
нет модуля менеджера, нет регистрации в `Преф_ОбщегоНазначения.НастроитьВариантыОтчетов`, нет
`variantsStorage` в `.mdo`. После добавления всех трёх отчёт открылся и сформировался.

Какая из трёх была причиной — не выяснено, и выяснять не стоит: у работающих отчётов есть все три.
Симптом «отчёт висит при открытии» — сначала проверить регистрацию по этой таблице, и только потом
техжурнал.

`variantsStorage` выставляется через `modify_metadata` (EDT-MCP 2.16+):
`properties: [{name: "variantsStorage", value: "SettingsStorage.ХранилищеВариантовОтчетов"}]` —
ровно одна строка в `.mdo`, без ручной правки.

На 2026-09-13 все 27 отчётов своих блоков (`Преф_`) зарегистрированы — модуль менеджера, список,
хранилище вариантов у каждого. Новый отчёт добавлять сразу со всеми тремя; проверка из раздела
«Грабля» выше должна давать пустой вывод.

## Порядок диагностики «вариантов не видно»

1. Есть ли у отчёта модуль менеджера с `ПриОпределенииНастроек`?
2. Есть ли отчёт в `Преф_ОбщегоНазначения.НастроитьВариантыОтчетов`, и нет ли там отчёта **без** модуля менеджера?
3. Есть ли раздел в `ОпределитьРазделыСВариантамиОтчетов` расширения?
4. Запускалось ли обновление ИБ после последней правки?
5. Смотрим в панель отчётов раздела, а не в навигацию.
