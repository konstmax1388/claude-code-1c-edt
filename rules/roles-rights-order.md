# Права ролей: порядок объектов в `Rights.rights` = порядок UUID

Правило появилось 2026-09-19 после четырёх суток потерянных обновлений. Цена ошибки: 15 часов зависания 17.09 и три
безрезультатные попытки 18.09 (агент EDT, `/LoadConfigFromFiles -listFile`, полная загрузка из файлов), 3,5 часа
полной выгрузки EDT 19.09. Диагноз: без изменённых ролей обновление прошло за 5 минут; две независимые причины — порядок блоков и права на Enum.

Применяется: при любой правке прав ролей (`src/Roles/<Роль>/Rights.rights`) не через конструктор EDT.

---

## Что происходит

EDT сериализует блоки `<object>` роли **в порядке возрастания UUID объекта** (UUID из `.mdo`; у членов объектов —
UUID реквизита/ТЧ/команды из `.mdo` владельца; стандартные реквизиты идут сразу за владельцем). Конфигуратор при
загрузке конфигурации в базу полагается на этот порядок. Блок, дописанный **в конец файла**, нарушает порядок, и
загрузка **зависает навсегда** — без ошибки, без записи в лог, с загрузкой ядра на 100 %. Симптомы одинаковы у агента
EDT и у пакетного конфигуратора: SQL не трогается, память замирает, процесс живёт часами.

Проверено сплошь на 861 роли конфигурации: у всех порядок по UUID выдержан (после исправления).

## Вторая причина: права на перечисления (`Enum.*`) — нельзя

Бисект 2026-09-19: упорядоченные роли с правами `Read/View` на `Enum.Преф_ПричиныНевыполненияПолива` висят так же
(19 мин без записи в базу), те же роли без строк `Enum.*` — обновление за минуты. Во всей конфигурации (861 роль)
права на перечисления не даёт никто: перечисления читаются без прав. **В ролях `Enum.*` не указывать.**

## Третья грабля: право на HTTP-сервис — только на уровне метода

`HTTPService.X` сам по себе прав не имеет: `Use` живёт на `HTTPService.X.URLTemplate.Шаблон.Method.Метод` (так во всех
типовых ролях: `HTTPService.ЭДО.URLTemplate.ЕстьНовыеДокументы.Method.POST`). Блок `<object><name>HTTPService.X</name>`
с `Use` EDT принимает молча, платформа при загрузке молча выбрасывает, а обратный импорт из базы его удаляет — так
2026-09-20 «пропали» права двух ролей обмена (план аудита 17.09 был с ошибкой).
Правильный план прав — по строке на каждый метод каждого шаблона.

## Как править права

1. **Предпочтительно** — EDT-API: `modify_metadata fqn=Role.X rights=[{object, right}]` (вставляет в правильную позицию).
   Известные отказы API: `View` у `Enum` и вложенные подсистемы (`Subsystem.A.Subsystem.B`) — падает с
   `Comparable.compareTo` / «Node not found», при этом часть прав уже применена.
2. **Файлом — только скриптом** (план прав в JSON → скрипт): вставка в позицию по UUID, права внутри
   объекта в порядке платформы (`Read, Insert, Update, Delete, …, Use, View, …`), CRLF сохраняется, после каждой роли —
   проверка порядка. Планы прав хранить в репозитории, чтобы переприменять после обновления типовой.
3. Перед обновлением базы, если роли трогались, — проверка порядка по затронутым ролям или сплошной прогон по всем:
   `scripts/check_rights_order.py` в этом репозитории.

**Никогда:** `t.replace('</Rights>', block + '</Rights>')` и любые «дописать в конец».

## Диагностика «обновление висит»

Порядок из `edt-infobase-deploy-troubleshooting.md` остаётся, но первым пунктом теперь:
**в пакете есть `Roles/*/Ext/Rights.xml`?** — снять роли из пакета (откатить файлы к предыдущему коммиту) и повторить
обновление. Прошло за минуты → виноваты роли, применить их скриптом. Список файлов пакета EDT —
`%TEMP%\1cedt\ssh-*\0\xml-inc-*\load.lst`.
