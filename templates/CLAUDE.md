# Правила работы ИИ-агента в EDT-проекте 1С

Положить в корень EDT-проекта, Claude Code подхватывает файл автоматически.
Каждое правило ниже появилось после аварии. Если правило мешает, сначала выяснить, какую аварию оно предотвращает.

## Контекст

- Конфигурация: <типовая, версия, платформа>. База тестовая: <имя>, сервер <...>.
- Свои объекты только с префиксом <ПРЕФ_>. Типовые объекты не менять без явной необходимости,
  правки типовых модулей обрамлять маркерами `// <<ПРЕФ` ... `// >>ПРЕФ`.
- Боевые базы агент не обновляет. Это делает человек.

## Запреты

1. Новые объекты метаданных (включая формы) создавать только в конструкторе EDT или через API EDT.
   Не писать `.mdo` и `.form` текстом: рукописный регистр ронял конфигуратор на реструктуризации,
   рукописная форма давала «Ошибка чтения формы» при выгрузке.
2. Не править `Configuration.mdo` вручную. Исключение: объект уже лежит на диске, а в составе его нет
   (ошибка «нельзя добавлять объекты метаданных без загрузки родительского объекта»).
3. Удалять объекты только через EDT.
4. Права ролей править через API EDT или скриптом со вставкой по UUID. Не дописывать блок в конец
   `Rights.rights`, не давать прав на `Enum.*`, права на HTTP-сервис давать на метод.
5. Не повторять операцию, упавшую по таймауту, пока не прочитан хвост `.metadata/.log` EDT.

## Рабочий цикл

1. Исследование до кода: метаданные, модули, справка платформы.
2. Код через запись модуля с проверкой синтаксиса, запросы через `validate_query`.
3. `revalidate_objects` и `get_project_errors` по своим объектам. Чистая валидация не означает готовность.
4. Для файлов, правленных мимо конструктора (`.dcs`, `.mxlx`, `Rights.rights`), запустить свою проверку.
5. Проверка на данных сплошной сверкой: явный счет «N из N, 0 расхождений».
6. Обновление тестовой базы только после окончания сборки EDT. Перед структурными изменениями нужен бэкап.
7. Коммит только своих файлов по списку, не `git add -A`.

## Диагностика

- Сначала факты: лог EDT, журнал регистрации, техжурнал, журнал Windows, `rac session list`. Потом гипотеза.
- Если на машине несколько кластеров, опознать свои `rphost` по версии в пути и `-regport`.
- Скрипт через `/Execute` под обычным пользователем идет в безопасном режиме. Привилегированный режим
  так не проверить, нужна реальная форма.

## Общение

- По-русски, коротко.
- Что не удалось проверить (вид формы, макет), сказать прямо и предложить проверить в конструкторе.
